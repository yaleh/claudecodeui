## 背景

语音输入链路今天只支持一种识别服务：OpenAI-compatible 的 `/audio/transcriptions`。配置面（`baseUrl` + `apiKey` + `sttModel`）看起来通用，但**协议形状被硬编码在三处**，所以换一个形状不同的服务不是配置问题，而是请求根本发不出去：

- **直连分支**：`src/shared/api.ts` 的 `transcribeVoice` 自己拼 multipart（字段 `file` 与 `model`、`Authorization: Bearer`、路径写死 `/audio/transcriptions`）。
- **代理分支**：`server/modules/voice/voice.service.ts` 的 `transcribe` 同样拼 `file` 与 `model`，URL 由 `resolveVoiceConfig` 给出的 base URL 加写死路径拼成。
- **响应解析**：同一处只认 `{ text: string }`；非 JSON body 被当作转写文本原样返回。

两条路径的字段名甚至不一致：直连发 `file`，代理发 `audio`，模型与密钥在代理路径上走 `x-voice-*` 请求头，而**没有任何 `x-voice-base-url`** —— 代理只认服务端环境变量里的 base URL。

而"多模态大模型作为识别服务"（例如 Gemini）的差异不在 URL，在能力面：它用 `generateContent` + 内联音频而不是 multipart，有 20MB 的内联上限，按音频 token 计费而不是按秒（因而没有 Groq 那个 10 秒/请求的计费下限），并且可以顺带给出标点、书面化风格与结构化输出。这些差异**在本仓库的代码里没有任何地方可以表达**。

### 为什么能力面不是"预留字段"，而是承重的

本仓库已经实测过若干条轴，每一条都对应一个真实效应，而不是推测：

| 轴 | 已测结论 |
| --- | --- |
| 提示词偏置 | 中文 + 出货裁剪下**有害**：句读由 2.31 掉到 1.25，标识符逐字存活由 33.3% 掉到 22.2%；英文未裁剪时才 +0.63 |
| 语言参数 | 已明确不采用：真实使用是混合语种，误判比不判更糟 |
| 换模型 | 换成 `whisper-large-v3` 无收益证据，两语种 CER 都更差 |
| 计费单位 | Groq 有 10 秒/请求下限；裁剪省下的 25.5%（中文）/ 13.3%（英文）就是对着这个下限算出来的 |
| 停顿线索 | 裁剪把**中文**句读打到 −89%，而 CER 只 +0.52pp —— **CER 对标点损失失明** |

最后两行构成一条设计级结论：**裁剪删掉的停顿，正是标点线索**。在按秒计费的服务上"裁了省钱"，在多模态大模型上"留着可能换回标点"。因此"裁不裁"必须成为识别器自己声明的属性，而今天没有任何地方能表达它。

### 验证通路的现状：缝已经存在，但在仓库外，而且与出货代码不是同一条

既往实验已经把"换识别器"的接口发明出来了：仓库外工装（`docs/experiments/README.md` 已登记其位置）里的 `tools/groq.mjs` 是唯一碰 HTTP 的模块，`transcribe(filePath, { prompt, language, responseFormat, model })` 是它的全部契约，换服务只需实现同名函数而所有 runner 不必改动。该接口已写入实验记录，是本 ADR 的直接依据。

但它在仓库外。仓库内能离线跑的实验只有 `experiments/voice-trim/` 下的 runner（冻结 fixture、不联网、量的是出货模块 `src/shared/voiceTrim.ts`）。而出货代码里的 ASR 调用是**内联在服务方法里的 fetch**，没有任何可 import 的纯模块。

结论：**今天无法在新识别服务上做任何"证明出货代码正确"的验证** —— 因为不存在一个既是出货实现、又能在命令行里直接调用的对象。

### 已有先例

`server/modules/providers/` 是本仓库"可插拔外部服务"的既定形态：`AbstractProvider` 的若干面 + `list/<id>/` 每服务一个目录 + `provider.registry.ts` 集中解析 + 一份"How to add a provider"的 README。本 ADR 的适配器形状**沿用该先例的词汇与布局**，而不是另发明一套。

### 与设计文档的分工

本 ADR 是一份更长的设计文档的**决策记录**：`docs/proposals/voice-asr-provider-seam.md` 承载完整论证（契约草稿、能力字段的逐条出处、文件布局、三处缺口的修改要求、分阶段实施）。本 ADR 从中取出**决策**，逐条补上代价与被否决的替代；设计文档保留过程与选项。

两者不一致时**以本 ADR 为准**（它是评审的对象），设计文档随评审结论一并修订。

## 决策

### 决策 1：差异用"适配器缝 + 能力声明"表达，不用配置字段表达

引入一层适配器：每个识别服务一个纯模块，导出一张 `AsrCapabilities` 与一个 `transcribe(request, invocation)`。调用方按 provider id 从 registry 解析，注入全部环境依赖（`baseUrl`、`apiKey`、`model`、`timeoutMs`、`fetchImpl`、`signal`）。

`invocation` 与 `request.hints.context`（发给模型的会话上下文）是两回事，命名上不得复用同一个词。

能力声明的字段与**每个字段为什么存在**：

| 字段 | 存在的理由 |
| --- | --- |
| `acceptsMime` | 不同服务接受不同容器；出货链路今天会在裁剪后把音频重编码为 WAV，而录音默认是 webm/opus |
| `maxInlineBytes` | 内联上限因服务而异（Gemini 20MB、multer 今天写死 25MB、Groq 又一个数） |
| `oversize` | 超限后的行为必须是显式声明（第一版只允许 `reject`），不能靠"上游会报错" |
| `honors.{prompt,language,context}` | 声明"发了有没有用"；声明为 false 时适配器必须**拒发**而不是静默丢弃 |
| `billing` | 秒 / 音频 token / 请求。决定省时长读数怎么折算，进而决定裁剪的性价比 |
| `pauseCues` | 停顿对该识别器是破坏性、中性还是有用。**驱动是否裁剪** |
| `style` | 能否给出书面化文本（见决策 5） |
| `oneShot` | 第一版只允许 `true` |

**代价：** 多一层间接。今天的 `voice.service.ts` 是"读配置 → 拼请求 → 解析响应"一段直线代码，拆开后要跨三个文件才看得见一次调用。另一处代价是新服务不再能靠"填 baseUrl"接进来 —— 必须写一个适配器文件。这是**有意的**：正是因为"填个 URL 就能接"这个错觉，才让今天这条缝不存在。

**被否决的替代：** 继续用配置字段表达差异（例如加 `protocol=openai|gemini` 分支，或在服务方法里写 `if (provider === 'gemini')`）。否决理由是分支会落在**两处**（直连分支与代理分支各一份），而两处一旦分叉，用户在"配了 baseUrl"与"没配 baseUrl"两种情形下会得到不同行为 —— 这正是本 ADR 要消灭的那类不一致。适配器缝的价值不在于少写代码，而在于**同一个实现同时服务两条路径**。

### 决策 2：适配器必须环境中立，落点是仓库根 `shared/`

适配器要同时用于浏览器（直连）、Node 服务端（代理）、命令行三处。因此它必须是环境中立的纯模块：只用相对导入、不碰 node 内建、环境依赖一律注入。

落点取**仓库根 `shared/`**，依据是两套编译配置的 include 事实（这不是偏好，是可核对的）：

- 根 `tsconfig.json` 的 `include` 含 `shared`；其 `types` 只有 `vite/client`，`lib` 只到 `ES2020` + DOM。
- `server/tsconfig.json` 的 `include` 含 `../shared/**/*.ts`，`rootDir` 为上一级，产物落进 `dist-server/shared/`；其 `exclude` 含 `../src`。

也就是说 `shared/` 是**唯一**被前端与后端两套编译同时纳入的目录。今天它只有一个文件（`shared/networkHosts.js`），消费者是服务端入口与构建配置 —— **已验证的组合是"构建工具 + 服务端"，尚未验证 `src/modules/**` 对它的导入**（见决策 3）。

由此直接推出四条硬约束，违反必然在其中一侧编译失败：

1. **只用相对导入，禁止 `@/`**：两套配置对同一个别名给出不同答案（根侧指向 `src`，服务端侧指向 `server`）。
2. **不碰 node 内建**：根侧的 `types` 里没有 node，`process`、`Buffer`、`node:*` 在此侧无类型。**这正是 CLI 入口不能放进 `shared/` 的原因**（它要用 `process.argv`）。
3. **`isolatedModules` 开着**：类型再导出必须写 `export type`。
4. **环境依赖一律注入**：既满足第 2 条，又让同一个适配器在三处同构可测。

"两套 tsconfig 同时编译同一份文件"这件事本身就是**环境中立性的机器判据** —— 它必须同时满足 `lib: DOM` + `moduleResolution: Bundler` 与 `lib: ES2022` + `NodeNext` + `types: node`。

CLI 因此放在 `experiments/` 下（裸 node 运行，与既有 runner 同形），而不是 `shared/asr/cli/`。提升为操作面命令（`cloudcli voice …` 子命令）留待验证闭环之后。

**代价：** `shared/` 不在 `.oxlintrc.json` 的 `boundaries/include` 里，因此适配器**默认不受 lint 覆盖**；要覆盖就必须同时登记 `boundaries/elements`，否则 `boundaries/no-unknown` 会把它判红 —— 两者必须同一个 commit 落地（本仓库已因"只登记一半"付过代价）。另有一处结构代价：`shared/` 的第三个消费者类型（前端模块）尚未被验证过，见决策 3。

**被否决的替代：** 放在 `server/modules/voice/providers/`（与 `server/modules/providers/` 的布局最一致）。否决理由是它与决策 7 冲突：直连模式下浏览器持有密钥并直接调用识别服务，服务端不在链路上；适配器若只住在 `server/`，浏览器就必须有第二份实现 —— 而那正是本仓库已经付过代价的失效（一次判据量的是工装里的副本而不是出货模块，16 条里 6 条与出货实现不一致）。

### 决策 3：边界探针是一个闸，且后备方案写死在本 ADR 里

决策 2 的落点依赖一个**尚未验证**的组合：前端模块导入 `shared/` 下的新模块。因此第一步必须是一个**边界探针**，且以实证为准：

1. 最小模块落在 `shared/`，从 `src/modules/**` 与 `server/modules/**` 各导入一次；
2. `npm run typecheck` 退出 0（两套配置同时编译同一份文件）；
3. `npm run lint` 退出 0，且 `.oxlintrc.json` 的 `boundaries/include` 与 `boundaries/elements` **同时**登记。

**若探针变红，后备方案是固定的：线协议实现只能有一个家，即 `src/shared/asr/`；服务端侧不新增 provider，直到边界问题解决为止。** 不允许的路径是"在 `server/modules/voice/providers/` 里再写一份线协议实现"。

之所以要把后备方案写在 ADR 里而不是留给落地时决定：一旦探针变红而人不在场，"再写一份"是最省事的下一步，而它会精确重演上面那条已付代价的失效。**把不可接受的下一步提前写死，是这条决策的全部内容。**

**代价：** 决策 2 的落点与决策 3 的后备方案会分叉出两种后续形态（服务端能不能接新 provider 取决于探针），后续任务的措辞因此要避免把服务端 provider 当成既定事实。另外探针本身是一个一次性判定 —— 它的**读数**可以判据化（见后续任务草案），但它的**结论**（落点是否成立）是人读的。

**被否决的替代：** 先按 `server/modules/voice/providers/` 开工、等真需要浏览器侧时再处理。否决理由是那时会被迫做二选一：要么把已经写好的服务端适配器搬走（并重写它的所有判据），要么接受两份实现。两条路都比先花一次探针贵。

### 决策 4：三处既有缺口由能力声明驱动修复，不新增全局常量

本次勘查发现三处既有缺陷。它们不因新 provider 才存在，但新 provider 会把它们从"缺陷"变成"错误"，因此纳入本 ADR 范围：

**缺口一：转写路由没有 MIME 白名单。** 上传只受大小限制，MIME 只做 `|| 'audio/webm'` 兜底。仓库内已有先例形状（资源模块的上传过滤器）。修法：白名单由所选 provider 的 `acceptsMime` 决定，**不新增第二个全局常量**；拒绝必须发生在读取上游**之前**，返回语义码且不消耗一次上游请求；客户端必须能拿到 `acceptsMime`，否则会出现"录了 webm、provider 只收 wav、白名单把用户自己的录音拒了"。

**缺口二：25MB 上限与 provider 的内联上限互不知情，是两个真相源。** 有效上限必须是 `min(全局硬上限, capabilities.maxInlineBytes)` 的**单一计算点**；超限返回 `OVERSIZE` 并映射为 **413** 而不是今天的 400（400 会让客户端以为是格式问题）。

**缺口三：健康检查只反映服务端环境变量，是单一真相源。** 它今天答的是"服务端配了吗"，而客户端只能自行补偿（用"已水合且 baseUrl 非空"当作可用）。修法：返回**当前用户的有效配置**加上 provider 列表与各自的能力；`configured` 字段的语义与位置不变以免既有消费者回归。

三处共同的形状是：**能力声明是唯一来源，客户端不再自行推导**（容器选择、裁剪判断、上下文开关都收敛到这一处）。

**代价：** 缺口三是行为变更（它今天给出的答案在一个真实用例下是错的），因此需要一条专门覆盖该用例的判据，而不是只测"字段还在"。缺口二的 413 是一个对外可见的状态码变更，会改变既有客户端对超限的解读方式。

**被否决的替代：** 把三处各自就地修掉（在路由里写一个 MIME 数组、把 25MB 改成 20MB、给健康检查加一个 provider 字段）。否决理由是它们会在下一次接入服务时全部重新失效 —— 三个常量、一个写死的数、一个只会说"服务端配没配"的探针，都不会随 provider 变化。

### 决策 5：输出信封扩为 `{ text, style, transformations }`

provider **优先**返回书面化 / 去口头语 / markdown 的文本，除非某服务经实验确认做不到（现有 whisper 系即属此类）。`text` 是已处理好的文本，composer 直接可用；另有两个声明字段：`style`（`verbatim` | `written`）与 `transformations`（`punctuate` / `de-disfluency` / `written-style` / `markdown` / `identifier-canonicalized` / `self-correction-applied`）。

`transformations` 不是装饰，它有三个机器用途：给 UI 一个"这条被改写了吗"的依据；给指标一个**选轴的依据**；给"还要不要继续跑客户端那层确定性标识符修复"一个判据（已声明 `identifier-canonicalized` 的文本不应被二次改写）。

**这带来一个必须直面的后果：现有判据会失明或失义。** 出货的标识符度量量的是**逐字存活**（大小写与点号敏感），而一份书面化文本本来就不逐字等于口语原话。因此指标必须分轴：

| 轴 | 适用 | 说明 |
| --- | --- | --- |
| 逐字标识符存活 | `style: verbatim` | 现有口径不变 |
| 语义等价 / 下游可理解 | `style: written` | 新口径 |
| 句读 / 片段 | 全体 | 先蒙掉标识符内部的点再计数 |
| CER | 全体（辅助） | **已知对标点损失失明**，不得单独作闸 |
| 账单 | 全体 | 按 `billing` 折算 |

新口径必须有一条**能红的负对照**：**含文件路径与代码片段的句子在风格化之后必须逐字保留**。书面化最容易顺手把 `voice.service.ts` 改写成 `voice service ts`，这条负对照就是量它。两个方向都要能红：若惰性实现（风格化根本没发生）也让判据全绿，那就没有测量任何东西。

**代价：** "更好"的判定变复杂了 —— 一份被改写的文本可能逐字退化而实际更好。这意味着逐字轴不能单独作闸，且新轴很可能**只能靠人读配对文本**（与标点位置合理性的先例一致），因此它不是 CI 判据而是一次性实验读数。

**被否决的替代：** 保持 `{ text }` 单字段、把书面化放到客户端后处理。否决理由是那需要第二套提示词与第二次模型调用，且会把"书面化"变成与识别器无关的固定行为 —— 而它恰恰是识别器能力的差异之一（有的服务能顺带给出标点，有的不能）。

### 决策 6：上下文偏置默认关闭，按服务分别测

会话历史、当前可见对话、项目文件树可以作为上下文一并发给识别服务，但：

- 由 `honors.context` 声明，**未声明的 provider 一律不发**；
- 载荷必须有界且可审（固定形状、字节上限、开关在 UI 可见）；
- **默认关闭**，且启用前必须让用户知道音频与上下文会一起送到第三方；
- 把某个 provider 打开，**必须附带该 provider 自己的配对实验**。

不预设结论：提示词偏置已实测在中文 + 出货裁剪下有害（句读与标识符双双退化），所以"给了上下文就更准"是**假设**，不是结论。同时要记录一条纪律：该实验记录已明确禁止用输出侧的差异（空格、词形）去解释输入侧的变化 —— 那是把待解释的现象换了个说法。

客户端那层确定性标识符修复（候选来自项目文件树）**独立于 provider 保留**：它不消耗模型调用、可离线判定，与"把同样的信息以提示形式给模型"不是替代关系。

**代价：** 上下文会连同音频进入第三方，是实质的隐私面扩大；启用后每次识别都多付上下文 token。另外它引入一个持续的验证义务 —— 每接入一个服务就要重跑一次该服务的配对实验，这不是一次性的工作量。

**被否决的替代：** 全局开关（一个"使用上下文偏置"的偏好，对全部 provider 生效）。否决理由是已有证据表明不同服务、不同语言、甚至同一服务的不同裁剪设置下结论相反；一个全局开关必然在其中一侧是错的，而且错得不可见（用户以为它提升了准确率）。

### 决策 7：保留直连拓扑，因此 provider id 的真相源必须在用户级配置

直连模式（浏览器持密钥、直接调用识别服务）保留。带来三个明确后果：

- 适配器必须环境中立（决策 2 由此而来）；
- 两条路径（直连 / 代理）都必须能把 provider 解析到同一份适配器；
- **浏览器持有密钥是既定设计而非缺陷**：服务端代理路径只是"用户没配 baseUrl"时的回落。这一点必须在设置页对用户可见，尤其是当 provider 是 Gemini 这类需要服务商密钥的服务时。

配置轴今天已经有三条（服务端环境变量兜底 / 用户级语音设置 / 语音总开关的 UI 偏好），加 provider 会变成第四条。**必须明确：provider id 只在用户级配置里，服务端环境变量只提供"默认 provider id"。** 不允许出现"环境变量说 A、用户配置说 B"而无从判断的情形。

**代价：** 新增 provider 必须在两条路径上都验证，不能只测一条。代理路径的字段与直连路径不同（代理今天发 `audio` 并走 `x-voice-*` 头，直连发 `file`），适配器必须吸收这个差异而不是把它留给路由。

**被否决的替代：** 取消直连、全部走服务端代理，从而让适配器只需存在于 `server/`。否决理由有两条：一是它会**删掉一项既有能力**（用户自带密钥直连自己的识别端点），二是有意绕开代理的部署（自建端点、区域限制）会因此失效。用"少写一层"换"删掉一项能力"不划算。

### 决策 8：区分"进 AC"与"只进实验记录"

本 ADR 的后续工作里，有两类东西**不能**判据化为 AC：

- **配对质量实验**（同一批语料跑多个条件，看标识符 / CER / 句读 / 账单）。它联网、按条件数计请求、单次约数秒 × 数十条，远超判据运行的时长上限；且其中至少一轴按既有先例只能靠人读。
- **每个新 provider 的常驻验证义务**（决策 6 的配对实验、决策 1 的 `pauseCues` 变更）。它随 provider 数量增长，无法用一组固定判据表达。

这两类的载体是 `docs/experiments/` 下的实验记录（沿用既有协议：配对比较不跨运行、必须有能红的负对照、被测实现必须是出货模块、报 `n`、串行执行、结果落盘缓存）。

**可以**判据化的是那些快、离线、确定的读数：命令行 `--dry-run` 的脱敏请求、`--offline` 的回放一致性、MIME 白名单的双向、超限状态码、健康检查的那个"环境变量未配置但用户配置了"的用例、不变量套件的五组、以及边界探针的机器部分。

**代价：** 质量结论不进 CI，因此质量回归不会自动被发现 —— 它依赖"每接入一个服务就写一份实验记录"这个人工义务。接受这个代价的理由是：一个联网、超时、靠人读的判据被塞进判据门之后，它的失败模式是"超时或不可判定"，而不是"发现质量退化"。

**被否决的替代：** 把质量读数也做成判据（例如"新 provider 的句读不低于基线的 X%"）。否决理由是阈值不可导出（语料是合成的、样本量小、效应方向明确而幅度不确定），一个拍出来的阈值会在下一次语料变化时变成假判据。既有实验记录已把"幅度"一侧明确登记为宽置信区间。

### 决策 9：既有"服务端保持纯透传"是阶段性约束，现提议修订

语音相关的两个目标都把"不改服务端语音接口契约：保持纯透传"写进了非目标。该条目**当时的语境**是裁剪与标识符修复都在客户端完成，服务端确实不必参与 —— 它是一条真实约束，不是随手一写。

引入适配器缝之后，服务端必须参与分派。修订方式不是删除该条目，而是**降级它的适用范围**：直连分支保持纯透传不变，"纯透传"从"服务端契约"降为"直连分支的性质"。

**本 ADR 只提议，不执行。** 修改 `goals/*.md` 由被授权的目标写入路径完成，且只追加修订记录，**不动两个目标已 achieved 的任何判据**。

**代价：** 两个已 achieved 的目标的正文会被改动。缓解方式是只追加修订记录、不改判据、不改状态，使"当时为什么这么定"与"现在为什么改"两段都留在文里。

**被否决的替代：** 不动既有目标，把修订意图只写在本 ADR 里。否决理由是那样会在仓库里留下两处互相矛盾的权威文本，而后续读目标正文的人（包括自动化的充分性判定）看到的是未经修订的那一份。

## 边界与不做的事

- **本 ADR 不实现任何东西。** 不写代码、不改任何既有实现、不改任何既有目标或判据。实现与判据化在评审通过后另行立案。

- **不做识别结果的持久化与审计。** 是否保存转写原文仍是一个未决问题，不在本 ADR 内裁决。
- **不给新阈值。** 文中引用的 20MB、25MB、10 秒下限、−89%、25.5% 等都是**既有代码、官方文档或既有实验记录里的既成数字**（且已注明出处），本 ADR 不新立任何阈值。
- **不写本机绝对路径。** 仓库外工装的位置以"`docs/experiments/README.md` 已登记"指代。
- **不点名任何未完成任务 id。** 后续工作只以本 ADR 的"后续任务草案"描述。
- **不裁决既有架构文档。** `docs/architecture/` 下与语音有关的断言是否需一并修正，留作评审时的开放问题。

## 后续任务草案

十条。每条给出判据与**取假变体** —— 取假变体指"刻意做一个假实现，这条判据必须因此变红"。判据若在假实现下仍是绿的，它测的就不是它声称要测的东西。

### 后续任务 1：边界探针与契约骨架

- **判据：** 一个最小模块落在 `shared/`，从 `src/modules/**` 与 `server/modules/**` 各导入一次；`npm run typecheck` 与 `npm run lint` 均退出 0；`.oxlintrc.json` 的 `boundaries/include` 与 `boundaries/elements` 同时含该路径。命令需打印两处登记的实际内容，缺一处时逐条打印缺失项。
- **取假变体：** 只登记 `boundaries/include` 而不登记 `boundaries/elements`。该变体必须让 lint 因 `boundaries/no-unknown` 变红 —— 这是本仓库已付过代价的那个坑的正面覆盖。
- **若探针红：** 转决策 3 的后备方案，本任务改为断言 `src/shared/asr/` 落点成立；**不得**新增服务端 provider。

### 后续任务 2：把现有实现抽成第一个适配器（行为零变化）

- **判据：** 纯重构。既有服务端语音测试与前端语音配置测试全部保持绿；且直连与代理两条路径经适配器后产生的出站请求（URL、头、体）**逐字节等于**改动前录制的基线。
- **取假变体：** 在抽取时顺手"统一"了字段名（例如把代理路径的 `audio` 改成 `file`）。该变体必须让基线比对变红。

### 后续任务 3：命令行（`--dry-run` / `--offline` / 真跑）

- **判据：** `--dry-run` **零网络**（用一个被禁止联网的 fetch 替身断言：发生调用即红）且打印的请求不含密钥与音频字节；`--offline` 回放录制响应，产出与录制一致的文本；真跑在真实音频上取回非空文本。
- **取假变体：** ① `--dry-run` 实际发出了请求（替身记录到一次调用）⇒ 必须红；② 脱敏只脱了密钥没脱音频 ⇒ 必须红；③ `--offline` 其实走了网络 ⇒ 必须红。

### 后续任务 4：不变量套件（对 registry 参数化，离线）

- **判据：** 五组各自成一条独立可红的断言：请求构造 golden（含"声明为不支持的提示参数必须**不发**而不是发空值"）、错误映射（401/403/429/5xx/超时/空响应/非 JSON 各归到哪个语义码）、大小分流、脱敏（密钥与音频字节不出现在返回值、错误消息、日志里）、MIME（不在 `acceptsMime` 内的输入在**发出请求之前**被拒）。
- **取假变体：** 把某个适配器的错误映射换成"一律返回上游错误"⇒ 401/429/超时三组必须红；把提示参数实现成"发空字符串"⇒ 第一组必须红。

### 后续任务 5：第二个适配器（多模态服务，仅内联）

- **判据：** 超过 `maxInlineBytes` 的输入返回 `OVERSIZE` 且**未发出任何请求**（替身断言调用次数为 0）；`honors.prompt` 为 false 时请求体不含提示字段；请求构造与响应解析各有 golden 基线。
- **取假变体：** 把超限音频直接塞进请求体 ⇒ 必须红（"调用次数为 0"这一半）；把响应解析写成"取第一个 candidate 的第一段文本"以外的宽松形式（例如把整个响应 JSON 当文本返回）⇒ 解析基线必须红。

### 后续任务 6：缺口一与缺口二（MIME 白名单、大小上限单源）

- **判据：** 白名单**双向** —— 白名单内的输入绿、白名单外的输入红且返回不支持 MIME 的语义码；有效上限随 provider 变化可观测（切换 provider 后读数改变）；超限返回 **413** 而不是 400；两条路径（直连 / 代理）产出同一个语义码。
- **取假变体：** ① 把白名单写成恒拒（全部拒绝）⇒ "内绿"那一半必须红；② 把上限写死回一个常量 ⇒ "随 provider 变化"必须红；③ 只改代理路径 ⇒ "两条路径同码"必须红。

### 后续任务 7：缺口三（健康检查反映用户有效配置）

- **判据：** 构造"服务端环境变量未配置、但用户配置了"的实例，断言 `configured` 为**真**；断言 provider 列表与各自能力齐备；断言既有 `configured` 字段的位置与语义未变（既有消费者不回归）。
- **取假变体：** 保留今天"只看环境变量"的实现 ⇒ 必须红。这条取假变体是本任务存在的全部理由 —— 今天这个用例会答错。

### 后续任务 8：风格化的双向负对照

- **判据：** 一条含文件路径与代码片段的句子，经 `style: written` 的 provider 处理后，其中的标识符**逐字保留**；同时在惰性实现下另一条断言必须红（"书面化确实发生了"）。
- **取假变体：** ① 风格化实现是恒等（不改写）⇒ "确实发生了"那一半必须红；② 风格化把标识符一起改写（`voice.service.ts` → `voice service ts`）⇒ "逐字保留"那一半必须红。两个方向都必须能红，缺一半这条判据就退化成一个恒绿断言。

### 后续任务 9：裁剪 × 识别器能力的接线

- **判据：** `pauseCues: destructive` 走裁剪；**默认行为不变** —— 既有的"裁剪开/关配对下上传体时长下降"端到端判据保持绿；`capabilities` 的读取成为裁剪决策的唯一来源。
- **取假变体：** 把默认改成"不裁"⇒ 既有时长下降判据必须红；把裁剪决策仍留在客户端各自判断（不读能力）⇒ "能力是唯一来源"必须红。

### 后续任务 10：配对质量实验记录（**不是 AC**，见决策 8）

- **判据：** `docs/experiments/` 下存在一份新记录，含同一批语料上的配对比较、报 `n`、并**带 `flat` 类的能红负对照**；命令断言负对照存在且被报告了方向（是否按预测方向移动）。
- **取假变体：** 去掉负对照，只报条件间的绝对读数 ⇒ 必须红。负对照缺失时，"指标变好"无法与"随便换个条件都有用"区分。
- **载体说明：** 本条判据只约束**记录的形状**，不约束质量数值 —— 数值属于实验结论，不进判据门。
